`multiconfig` 里的时间戳是 `2015-09-09`。

`CScript` 的选择点在 `Core::CAppClient::CAppClient` @ `0x266460`：

`2 → CScriptAS3` 一个分支；`0` 返回空。

## AS3 虚拟机

`libShellClient.so` 里嵌的是 **Tamarin AVM2**（avmplus + MMgc + avmshell）；
`.so` 里没有 Scaleform/GFx 符号：

- `Gamma::CScriptAS3`（字符串出现 242 次，含类/方法/vtable 名）
- `tamarin::CreateTamarin` @ `0x37fdb0`
- `tamarin::Avm2CoreImpl`、`avmplus::ScriptObject`、`MMgc::GC`
- `avmshell::handleDoABC2` / `SwfParser`
- `CScriptAS3::CScriptAS3` @ `0x37bed8` 里注册了内置对象：
  `String`、`ByteArray`、`Matrix3D`、`Vector3D`、`Point`、`Rectangle`，
  以及 `ClassCast`
- **没有** `Gamma::CScriptLua`、`lua_newstate`、`LuaJIT`、`lua_*`

`avmshell` 直接解析 SWF 的 `DoABC2`，所以 `DeltaxCpp.swf` 和 `Main.swf`
都由同一个 AS3 VM 执行。

绑定细节：AS3 的 `native` 方法由 Tamarin 的 `CNativeInitializer`/
`CNativeScriptObject` 承接；`tamarin::BindCppObject` / `GetBindingCppObject`
在 AS3 对象里存/取 C++ 指针；`CScriptAS3::RegistClass*` 把类和方法登记到
`CClassRegistInfo`。`ClassCast` 再按目标 AS3 类创建新的 `ScriptObject`
并重绑同一个 C++ 指针。

## `DeltaXCpp.swf`：AS3 运行时 / C++ 绑定层

`DeltaXCpp.swf` 不是游戏本体，而是 **DeltaX 的 AS3 运行时和原生绑定层**，
对应 `version.inf` 的 `[DeltaXCode]`。实际文件名前缀是 `DeltaxCpp_`
（小写 x），引擎代码里的模板名也是 `DeltaxCpp`；`DeltaXCode` 是段名。
文档类是 `deltaxcpp.DeltaxCpp extends deltaxcpp.appframe.Application`。

247 个脚本，大致三类：

| 类别 | 数量 | 例子 |
|---|---:|---|
| `deltax.*` 接口/框架 | 149 | `IApplication`、`BaseApplication`、`DeltaXWindow`、`DeltaXRenderer`、`IGUIManager`、`IResourceManager` |
| `deltaxcpp.*` 具体实现 | 13 | `Application`、`DeltaXRenderer`、`ResourceManager`、`LoaderManager`、`Sound2D`、`ConnectionToGameServer` |
| 根级 `C*`/`I*`/枚举 | 85 | `CApplication`、`CBaseAppClient`、`CRenderer`、`CGWnd`、`CResourceManager`、`CLogicObject`、`CLogicScene` |

`.so` 的 `0x5e5570` 起有一张类名表（`CBaseCommon`、`CBaseApp`、`CApplication`、
`CRenderer`、`CGWnd`、`CGButton`、……），与 DeltaXCpp 的根级 `native`
声明一一对应。

根级 `C*` 类都是 `native` 声明，例如：

```as3
public class CApplication extends CBaseAppClient {
    public static native function GetInstance() : CApplication;
    public native function SetHandler(param1:IAppHandler) : void;
    public native function GetRenderer() : CRenderer;
    public native function GetGUIManager() : IGUIMgr;
    public native function ConnectServer(param1:String, param2:uint) : CLogicConnection;
    ...
}
```

接线方式：

- `deltaxcpp.appframe.Application` 构造时
  `this.m_appCpp = CApplication.GetInstance(); this.m_appCpp.SetHandler(this);`
  原生 `Core::CApplication::SetHandler` @ `0x1d1764` 把 AS3 对象存进
  `this+52`，后续每帧回调 `IAppHandler` 的 `OnStart`/`OnClose`/`OnCheckFrame`/
  `OnRenderBegin`/`OnRenderEnd`/`OnUserCmd`/`OnAllLoadingDone`。
- `Application.OnStart` 再取 `BaseApplication.instance`（也就是 `Main.swf` 里的
  `webguyu.Game`），调用它的 `onInit()` / `onStarted()`，把控制权交给游戏层。
- `Application` 还负责创建 `DeltaXRenderer`、`ResourceManager`、`LoaderManager`、
  `ConnectionToGameServer`、`Sound2D`，并把 `guiManager`、`renderer`、
  `resourceManager`、`loadManager`、`curLogicScene` 暴露给游戏 SWF。
- `External.ClassCast(param1, param2)` →
  `ExternalInterface.call("ClassCast", ...)`；在嵌入 VM 里由
  `CScriptAS3::ClassCast` @ `0x37a0c4` 接管：按类名找到目标 AS3 类，
  检查继承关系，把同一个 C++ 对象重新绑到新的 AS3 `ScriptObject`。
  这和 Lua 版的 `ClassCast` 是同一思路。
- `DeltaxCpp` 构造函数把 `TableFile.s_TableFileImpCreate` 指向
  `flash.utils.TabFile`；`TabFile` 是 C++ 注册的原生类，AS3 读表实际走
  `CTabFile`。

## `Main.swf`：游戏本体

`Main.swf` 的文档类 `Main extends Sprite`，构造函数里只有一句
`private var m_game:Game = new Game();`；
`webguyu.Game extends deltax.appframe.BaseApplication`。

1,928 个脚本：

| 包 | 数量 | 说明 |
|---|---:|---|
| `webguyu.*` | 1,757 | 游戏 UI、角色、场景、技能、任务、商店、PVP、活动 |
| `deltax.*` | 169 | 同一套 DeltaX AS3 框架的编译副本 |
| `flashx.*` | 1 | 扩展 |
| `Main` | 1 | 文档类 |

> 注意：`Main.swf` 自己也有 169 个 `deltax.*` 类（与 `DeltaXCpp` 的 149 个有重叠），
> 说明它是带着 DeltaX AS3 框架编译的；运行时由同一个 Tamarin VM 解析，
> 不能只按“类在哪个 SWF”判断归属。但 `Main.swf` 没有根级 `C*.as` 原生包装
> （根目录只有 `Main.as`），这些包装只在 `DeltaxCpp.swf` 里。

游戏侧关键类都在 AS3：

- `webguyu.character.Character extends ShellLogicObject`
- `webguyu.scene.GameScene extends ShellLogicScene`
- `webguyu.character.player.main.MainPlayer extends Player`
- `webguyu.skill.SkillManager`
- `webguyu.character.AI.BossAI.*`

`webguyu.Game` 在 `onStarted` 里把游戏类注册到原生对象类型：

```as3
m_appImpl.registerClass(MainPlayer, 0, ObjectClassID.DIRECTOR_CLASS_ID);
m_appImpl.registerClass(Npc, Npc.SERVER_CLASS_ID, ObjectClassID.FOLLOWER_CLASS_ID);
m_appImpl.registerClass(ClientNpc, ClientNpc.CLIENT_CLASS_ID, ObjectClassID.PERFORMER_CLASS_ID);
m_appImpl.registerClass(Player, Player.SERVER_CLASS_ID, ObjectClassID.FOLLOWER_CLASS_ID);
m_appImpl.registerClass(GameScene, 0, ObjectClassID.GAMESCENE_CLASS_ID);
m_appImpl.registerClass(this.getShellConnect, 0, ObjectClassID.GAMECONNECT_CLASS_ID);
```

`libShellClient.so` 里没有 `webguyu`、`CPlayer`、`CGameScene`、`CManor`
这些游戏类；它只提供引擎对象（`CLogicObject`/`CLogicScene`/`CRenderer`/
`CGWnd`/`CResourceManager`/网络）和 `CGameAppClient` 外壳。
**所以这一版的游戏逻辑和 UI 在 AS3，不在 .so。**

## 加载顺序

1. `CGameAppClient::CGameAppClient` @ `0x1c8770` 调
   `CApplication::CApplication(this, "Main")`；shell 基础名是 `Main`。
2. `CApplication::OnNewCodeVersionRetrieved` @ `0x1d3fc8` 从 `version.inf`
   读 `[DeltaXCode]` / `[ShellCode]` 的版本，拼出
   `DeltaxCpp_<version>.swf` / `Main_<version>.swf`。
3. `CApplication::GetDefaultSwfPathName` @ `0x1d30a0` 读
   `gac_config.xml` 的 `<SWF Path>`，再拼 `_<version>.swf`。
4. `CApplication::OnSwfLoaded` @ `0x1d3320` 先用 `DeltaxCpp` 字符串和
   `Main` shell 名判断当前加载的是哪一个；先运行 `DeltaxCpp`，随后触发
   `Main` 的加载。两者都走 `CScript::RunBuffer` → `CScriptAS3` →
   Tamarin `avmshell` 的 `DoABC2`/`SwfParser`。

## `misc/ShellCommon` 的 Lua

`misc/` 下只有 `ShellCommon`（没有 `ShellClient`）：
`assets/misc/ShellCommon/a108175294bb5474e2bec646b944cd41.r` 里有 9 条
**Lua 5.1 字节码**（`1b 4c 75 61 51`），源路径是
`D:/13a/src/game/cpp/game/lua/ShellCommon/*.lua`。

但本包 `.so` 里没有 Lua VM（`CScriptLua`/`lua_newstate`/`LuaJIT` 都是 0），
客户端不会执行这些字节码。内容也偏公共逻辑（`Task_design`/`Task_inc`/
`SkillCommon`/`LuaTableFile`），更像 13a 服务端/工具共用库，而不是这个
AS3 客户端的 UI 脚本。**不要用 `/misc` 是否存在判断脚本后端。**

## 识别 AS3 构建的清单

1. `etc/gac_config.xml` 有 `<Script>as3</Script>` 和 `<SWF Path="..."/>`
2. `assets/bin/release/` 有 `DeltaxCpp_<md5>_<ver>.swf` + `Main_<md5>_<ver>.swf`
3. `version.inf` 有 `[DeltaXCode]` 和 `[ShellCode]`
4. `.so` 里 `CScriptAS3`/`tamarin`/`avmplus`/`MMgc` 存在，
   `CScriptLua`/`lua_newstate`/`LuaJIT` 为 0
5. `Main.swf` 的 ABC 里有 `webguyu.*`（或对应项目包名），`.so` 里没有这些类

## 结论

- 全民猎妖/雷霆射击是 **AS3 Gamma**：`CScriptAS3` + Tamarin，游戏逻辑和 UI
  在 `Main.swf`，`.so` 是引擎与绑定层。
- `DeltaXCpp.swf` 是 **DeltaX AS3 运行时/原生桥**（`[DeltaXCode]`），
  先于 `Main.swf` 加载，负责 `CApplication`/`CGWnd`/`CRenderer` 等原生类的
  AS3 包装、`IAppHandler` 生命周期回调、`ClassCast` 和 `TableFile`。
- `misc/ShellCommon` 的 Lua 文件在此 build 里是死数据；判断脚本后端要看
  `<Script>` 和 `.so` 里的 `CScriptAS3`/`CScriptLua` 符号。
